# GameDream M1 Sprite/Animation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native). Steps use checkbox syntax.

**Goal:** Replace the M1 colored rectangles with data-driven sprite sheets and idle/move/attack animations. Add `system.sprites`, SVG sprite sheets, sprite configs, and a `GAMEDREAM_SPRITE_OK` marker. M0/fixture keep the polygon fallback.

**Architecture:** `ContentDB` loads `game/content/sprites/*.json`. `system.sprites` builds `SpriteFrames` from a texture + frame size + animation ranges, producing per-frame `AtlasTexture`s. Player/enemy scenes keep the existing Polygon2D as fallback and add a hidden `AnimatedSprite2D`; when the service applies a config, the fallback hides and animation state follows movement/attacks.

**Tech Stack:** Existing composer + Godot 4.4 `AnimatedSprite2D`/`AtlasTexture`; SVG sprite sheets imported by Godot; headless autoplay.

## Global Constraints

- Content stays in `game/content/sprites` and is user-owned; copy-if-missing only.
- Sprite config: `{ id, texture, frame_size: [w,h], animations: { name: { frames, fps, loop } } }`.
- Textures are SVG sprite sheets in module `assets/`; no external download.
- M1 marker order: `BOOT_OK, MAP_OK, SPRITE_OK, DIALOGUE, LEVEL_UP, EQUIPPED, SKILL_CAST, LEVEL_2, QUEST_COMPLETE, WIN`.
- M0/fixture have no `system.sprites`; fallback polygons stay visible and markers are unchanged.
- Sprite application must tolerate missing config, missing texture, bad frame size, and empty animations.

## Review Focus

1. Sprite config loading and fallback.
2. SpriteFrames/AtlasTexture construction and SVG import.
3. Player/enemy animation state transitions (idle/move/attack) without breaking combat.
4. Marker once per run; M0/fixture fallback.
5. Save/load/new-game compatibility.
