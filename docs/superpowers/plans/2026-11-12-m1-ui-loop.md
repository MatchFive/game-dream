# GameDream M1 UI Loop Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native). Steps use checkbox syntax.

**Goal:** Make the generated M1 project feel like a game: main menu, inventory/equipment/skill screens, pause menu, save/load, and HUD level/XP. Gameplay and the five headless markers must remain unchanged.

**Architecture:** Add `core.save` plus five UI modules (`ui.main_menu`, `ui.inventory_screen`, `ui.equipment_screen`, `ui.skill_screen`, `ui.pause_menu`). Composer mounts every module `ui_mounts` entry into `main.tscn` (HUD + screens), not just the HUD. UI modules declare toggle input actions; `InputMapSetup` registers them. Gameflow/gameplay are untouched except HUD progression display.

**Tech Stack:** Existing composer + Godot 4.4 UI (Control nodes), JSON save file, headless autoplay.

## Global Constraints

- UI scenes are `CanvasLayer`, hidden by default except main menu; toggle actions:
  - inventory `I`, equipment `C`, skills `L`, pause `Escape`.
- Main menu hidden in headless (`DisplayServer.get_name() == "headless"`).
- Pause menu uses `process_mode = ALWAYS` so it can unpause.
- `core.save` serializes `inventory`, `progression`, `equipment` via their `serialize/deserialize` methods.
- Existing M1 markers remain: `GAMEDREAM_BOOT_OK`, `GAMEDREAM_LEVEL_UP`, `GAMEDREAM_EQUIPPED`, `GAMEDREAM_SKILL_CAST`, `GAMEDREAM_WIN`.
- `rpg-action-m0` and `fixture-minimal` keep working (fewer UI mounts).
- No quests/dialogue/levels in this plan (Plan 6).

## Review Focus

1. Main scene must mount every `ui_mounts` entry with the right layer; fixture/m0 must not gain missing scenes.
2. UI toggles must not break headless autoplay or pause the tree unintentionally.
3. Save must tolerate missing services and never corrupt the existing save on failure.
4. Content UI must read ContentDB/services, not hardcode item/skill names.
5. HUD level/XP must initialise from progression, not only from later events.
