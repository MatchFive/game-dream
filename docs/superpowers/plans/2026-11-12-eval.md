# GameDream Eval Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native). Steps use checkbox syntax.

**Goal:** Add `dream eval` with a 20-prompt model-free regression suite. Each case runs prompt → `draftGameSpec` → `selectTemplate` and checks expected genre/template. `--provider openai` runs the same cases against a real model.

**Architecture:** A JSON prompt fixture (`fixtures/eval/prompts.json`) holds prompt, expected genre, and expected template. `evalCommand` uses an injectable `ModelProvider` (fake by default), runs cases sequentially, records pass/fail/errors, and exits 2 on any failure. CLI `dream eval` exposes fixtures/templates/provider/json.

**Tech Stack:** Existing agent `draftGameSpec`/`selectTemplate`, commander, Vitest. No model calls in CI.

## Global Constraints

- 20 cases, unique prompts, expected genre + template.
- Fake provider makes the suite deterministic and offline.
- A case fails if schema validation throws, genre mismatches, or template mismatches.
- One failed case does not abort the suite; all results are reported.
- `--provider openai` requires `OPENAI_API_KEY`; no key is needed by default.
- Eval does not scaffold or run Godot projects.

## Review Focus

1. 20 fixtures and expectations match actual template selection.
2. Case failures are isolated; summary/exit code correct.
3. Provider injection/default/fake behavior; JSON output.
4. CLI flags/paths and no-key behavior.
5. No regression to agent/create paths.
