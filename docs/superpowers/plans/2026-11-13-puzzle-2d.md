# Plan 46: Playable Sokoban Puzzle Slice

## Goal

Move the `puzzle` benchmark case from `fallback` to `playable`, and fix its
misclassification as action-rpg.

## Scope

- Puzzle classification rule and fake-provider genre inference.
- Sokoban board with walls, targets, boxes, and a player.
- WASD movement and one-box pushes; two levels.
- Push and win markers.
- Headless BFS over player/box states to solve both levels for G3.
- HUD and a visible board.
- Same create/compose/G1/G2/G3/G6 path as other cases.

## Implementation

- `modules/system.puzzle`: ASCII levels, move/push rules, BFS solver, `_draw`.
- `templates/puzzle-2d`: template manifest selecting the module.
- `fixtures/specs/puzzle.yaml`: direct compose fixture.
- Updated template selection, fake provider, eval expectations, benchmark test,
  and fixture module inventory.

## Evidence

- Real Godot: G1/G2/G3 pass, G6 pass (1280×720, 20 colors).
- Markers observed: `GAMEDREAM_PUSH`, `GAMEDREAM_WIN`.
- Benchmark: `6 playable / 0 fallback / 0 failed`, exit 0.
- Existing action-rpg, platformer, shooter, roguelike, tower-defense unchanged.
- UE remains deferred.

## Limits

- Godot-only slice; Web/Unity puzzle parity is not claimed.
- Two small built-in levels; no level editor or undo stack.
